# 开发与维护手册

这份文档面向**要改这个项目的人**：构建怎么做、测试怎么跑、发版要注意什么，
以及若干个已经踩过的坑（坑的部分请务必留神，有些问题很隐蔽）。

只想用这个网站的话看[项目首页](../README.md)就够了。

## 仓库结构

刻意分成三块：**发布目录只放网站本身**，工具和文档放在外面 ——
这样分享出去的链接里不会出现构建脚本、测试脚本这些东西。

```
global-tv/          可部署的网站（部署时上传的就是它，只有网站本身）
                    纯静态：index.html + assets/，没有构建步骤
globetv-dev/        构建与测试脚本（不部署）
docs/               本文档与 README 配图
```

`global-tv/` 里比较关键的几处：

```
global-tv/
├── index.html                  页面骨架 + 首屏并行策略（内联脚本）
└── assets/
    ├── css/style.css           全部样式（含深浅两套设计令牌）
    ├── js/
    │   ├── globe.js            地球仪：着色器、亮点系统、拖拽/缩放/命中检测
    │   ├── player.js           播放器：HLS、线路切换、播放列表
    │   ├── app.js              主逻辑：数据索引、筛选、搜索、抽屉、联动
    │   ├── boot.js             数据加载（gz 解压）+ 启动调度
    │   ├── changelog.js        更新记录（发版时改这里）
    │   └── app.bundle.js       ↑ 上面 5 个的合并产物（线上只加载这一个）
    ├── img/earth-{dark,light}.jpg   4096×2048 等距圆柱投影贴图
    └── vendor/                 three.js r150；hls.js（按需加载）
```

⚠️ **`global-tv/` 这个目录名不要改**：线上应用的关联是按目录路径记录的，
改名会断开关联、生成新链接。同理，部署时的 `directory` 参数必须始终指向它。

原始 API 缓存（约 17MB）放在仓库**外面**（`../.globetv-cache/`，已 gitignore），
想换位置就设环境变量 `GLOBETV_CACHE`。

## 本地开发

```bash
# 普通 HTTP（够日常改样式/逻辑用）
cd global-tv && python -m http.server 8777

# HTTPS（自签证书，需要验证「仅 HTTPS」筛选、混合内容拦截等行为时用）
cd globetv-dev && python serve_https.py 8443
```

`serve_https.py` 会在首次运行时用 openssl 自动生成自签证书到 `.devcert/`（已 gitignore）。

两个容易忘的点：

- 所有浏览器测试脚本都要带 `--ignore-certificate-errors`。
  否则 Chrome 会停在「您的连接不是私密连接」页面，脚本会以「页面未就绪」的形式**静默跑偏**。
- 涉及 `requestFullscreen()` 的测试**必须用真实鼠标事件**（`Input.dispatchMouseEvent`）。
  用 JS 调 `element.click()` 会被浏览器以 `Permissions check failed` 拒绝，
  因为全屏要求用户手势。

## 构建

```bash
cd globetv-dev
python build_data.py     # 拉数据 + 绘地球贴图  → global-tv/assets/
python bundle.py         # 合并 5 个 JS 源文件 → global-tv/assets/js/app.bundle.js
```

`build_data.py` 依赖只有 Pillow，做的事：

1. 从 iptv-org 拉 channels / streams / countries / categories / logos（带本地缓存）
2. 按「HTTPS 优先 → m3u8 优先 → 清晰度」挑选每个频道的线路，最多留 5 条
3. **按真实国界采样**给每个频道分配坐标（见下文「亮点落点」）
4. 产出 `channels.js` + `channels.json.gz`（同一份数据的两种封装）
5. 用 Pillow 把世界地图画成两张 4096×2048 的等距圆柱投影贴图

⚠️ **改了 `global-tv/assets/js/*.js` 后必须重跑 `bundle.py`**。
页面加载的是 `app.bundle.js`，不重新打包的话改动不会生效 —— 这是最常见的"改了没反应"。

## 自测

全部在 `globetv-dev/` 下执行，截图落在 `globetv-dev/.shots/`（已 gitignore）。
这些脚本用 CDP 驱动**真实浏览器**做端到端验证，不是单元测试。

```bash
python verify_placement.py        # 亮点有没有落到海里、贴图有没有假线（秒级，改撒点/贴图后必跑）
node geotest.js <URL>             # 贴图与亮点的地理定位是否对齐
node verify.js <URL>              # 全流程交互 + 截图
node verify_https.js              # HTTPS 全流程 + 线路可播率抽测（默认跑本地 8443）
node verify_mobile.js <URL>       # 手机端触摸：点亮点、命中容差、抽屉、播放器
node verify_markers_perf.js <URL> # 亮点数量、帧率、命中延迟、点击命中
node verify_markers.js <URL>      # 亮点「可辨为薄荷绿」占比
node verify_globe.js <URL>        # 地球可见性：对比度、亮点、贴图失败兜底
node verify_fullscreen.js <URL>   # 更新提醒、中央三角、全屏控制条
node verify_center_clean.js <URL> # 播放时画面正中是否真的没有按钮
node verify_live.js <URL>         # 对线上链接确认「真的能解码出画面」
node scan_lon.js <URL>            # 多经纬视角球盘亮度（改完贴图颜色后必跑）
node timing.js <URL>              # 首屏时间线，定位串行等待
```

调参用的两个：

```bash
node tune_dots.js <URL>           # 批量试亮点尺寸，不用改代码
node tune_markers.js <URL>        # 批量试亮点配色，不用改代码
node make_preview.js <URL>        # 生成 README 配图到 docs/images/
```

**A/B 类验证的一个前提**：对比「亮点开/关」或「控制条开/关」时，
必须先把**视频暂停**（直播画面逐帧在变，差分会被画面运动淹没），
旧版有自转的还要先冻住（注入 `idle = -1e9`），否则量到的是旋转差异。

## 发版流程

1. 改代码（`global-tv/assets/js/*.js`）
2. **跑 `python bundle.py`**
3. **写更新记录**：编辑 `global-tv/assets/js/changelog.js`
   - 把 `current` 改成新版本号（沿用 `年-月-日.序号`，如 `2026-10-14.3`）
   - 在 `entries` 数组**最前面**加一条（最新的在最上）
4. ⚠️ **再跑一次 `bundle.py`** —— `changelog.js` 也在打包范围里，
   漏掉这步线上代码会更新但版本号不变，用户就收不到更新提醒
5. 部署，链接不变

用户下次打开时，页面拿 `current` 和本地 `localStorage['globetv.seenVersion']` 比对，
不一致就点亮右上角小圆点并自动弹出说明；首次访问（本地无记录）只静默记下，不弹窗。
清掉站点数据或换浏览器会再弹一次，属预期行为。

## 首屏为什么这么排

线上静态托管有两个现实约束：**不做 gzip**，而且**每个请求有 1~2 秒的基础延迟**（连 2KB 的 favicon 都要 2 秒）。
所以首屏策略是「少发请求 + 全部并行」：

- **数据预压缩**：静态托管不发 `Content-Encoding: gzip`，于是数据额外产出一份 `channels.json.gz`
  （3.1 MB → 0.68 MB），由 `boot.js` 用浏览器原生 `DecompressionStream` 解压。
  老浏览器 / `file://` 直开自动退回未压缩的 `channels.js`。
- **内联脚本抢跑**：`<head>` 里的一小段内联脚本在解析阶段就做三件事 —— 定主题（避免浅色用户先闪一下深色）、
  预加载对应主题的地球贴图、立刻开始请求 `channels.json.gz`。这样数据下载与 `three.min.js` 是并行的，
  而不是等所有脚本下载完才开始（那会白白多等十几秒）。
- **合并脚本**：`globe/player/app/boot` 四个文件合成 `app.bundle.js`，少 3 个请求。
- **hls.js 按需加载**：405 KB 的解码库只有真的要播 HLS 时才注入，不占首屏。

结果：首屏请求从 10 次降到 6 次且全部并行。

## 亮点落点：必须用真实国界采样

**背景**：一开始的撒点写法是「以国家质心为圆心、按国土面积估一个半径，按黄金角撒开」。
对圆形国家还行，但对长条形和不规则国家就废了 —— 智利、挪威、印尼这类国家，
点会直接撒到旁边的海里。实测 **15.5% 的频道坐标落在海上**，用户一眼就看出来了。

**现在**：`build_data.py` 从 world-atlas 的 110m 拓扑数据里解出每个国家的国界多边形
（拓扑里的数字代码 ccn3 通过 world-countries 映射成 ISO2，174/174 全部映射成功），
然后在**多边形内部**做抖动网格采样：

- 格距由多边形面积（鞋带公式，且扣掉内环，比如南非里的莱索托）估算，取不够就缩小重试
- 点在多边形内测试用射线法，先过外环 bbox 快速排除
- 采样结果打乱后取前 n 个，保证分布均匀而不是"只覆盖上半部分"

实测落海比例 **15.5% → 1.14%**。剩下的 1.14% 基本都是 110m 分辨率下不收录的小岛国
（新加坡、马尔代夫、马耳他、阿鲁巴…），它们没有多边形可采样，只能退回到质心撒点，
半径按真实面积缩放并把下限压到 0.18°，尽量贴着本国。

另外两处必须注意的坑：

1. **反经线（±180°）**：俄罗斯、斐济、新西兰、阿拉斯加的国界会绕过去。
   原始坐标在接缝处从 +180 突跳到 -180，直接画出来就是一条**横穿整幅地图的长线** ——
   实测贴图在纬度 65°、71° 各有一条 2000+ 像素的假线（占满整幅宽度）。
   处理办法是先把环的经度解成连续值（`unwrap_ring`），再补 ±360° 的副本绘制。
2. **环绕极点的环（南极洲）**：数据用一条贴着最低纬度（-85.6°）的人为闭合边收口，
   直接画会导致极点被涂成海洋、冰盖中间多出一条假海岸线。
   现在把那条人为边切掉、海岸按开口折线画，并补一块到极点的填色。

这两个问题都靠 `python verify_placement.py` 检查，改完撒点或贴图后记得跑一次。

## 地球可见性：贴图颜色不能贴着纯黑 / 纯白

这是踩过的一个大坑，改动贴图前务必先读这一节。

**现象**：用户反馈「地球是黑的」。排查后确认**贴图是加载成功的**，问题在于贴图颜色本身贴着了纯黑：
深色主题的海洋原本是 `(10,12,15)`，经过光照（`ambient 0.42 + diffuse`）后只剩 5~15 —— 而地球表面
**71% 是海洋**，所以只要转到太平洋那一面，整个球就和页面底色 `#18191b` 糊成一片纯黑，只剩绿点浮在空中。
浅色主题则相反：海洋 `(214,219,226)` 和页面底色 `#e9ebee` 几乎同色，地球直接"隐身"。
两种显示器链路（HDR 屏、系统对比度增强）会进一步把这种贴边的颜色压没。

**现在的取值原则**（`tools/build_data.py`）：

| 主题 | 海洋 | 陆地 | 要求 |
| --- | --- | --- | --- |
| 深色 | `(27,35,44)` | `(50,58,68)` | 必须明显亮于页面底色 `#18191b` |
| 浅色 | `(148,162,178)` | `(208,215,224)` | 必须明显暗于页面底色 `#e9ebee` |

实测球盘均值 vs 页面底色：

| 场景 | 球盘均值 | 背景 | 对比度 |
| --- | --- | --- | --- |
| 深色 · 非洲（有陆地） | 93.0 | 25.5 | 67.5 |
| 深色 · 太平洋（整屏是海，最坏情况） | 56.3 | 25.5 | 30.8 |
| 浅色 · 非洲 | 189.1 | 230.7 | 41.6 |
| 贴图加载失败（兜底色） | 88.4 | 25.5 | 62.8 |

另外球体还做了三层兜底，保证**任何情况下都不会是一个黑洞**：

- 贴图未就绪或彻底加载失败时，着色器用 `uHasMap=0` 走兜底色 `uBase`（深蓝灰），而不是采样未绑定纹理（那会返回 `(0,0,0)`）。
- 贴图加载失败会自动重试 3 次（退避 0.6s / 2.4s），同一张图只会发一次请求（`_texLoading` 去重）。
- 启动画面会一直保留到贴图真正挂上（最多等 9 秒），避免看到"还没贴图的黑球"那一帧。

改完贴图后请跑 `node tools/verify_globe.js <URL>` 复验上面的对比度表。

#### 陆地网点已移除

贴图原本还在陆地上叠了一层 `step=9, r=1.5` 的半调网点（深色下近灰青色 `(176,210,204,34)`），
后来整体删掉了 —— 用户反馈那片灰色点点很影响观感。现在陆地是纯色块，只靠海岸线 / 国界线勾轮廓。

验证方法（比看截图可靠）：网点是 **9px 周期**，所以取一行陆地像素做**自相关**，
看 lag=9 是否明显突出。移除前的实测值 0.20~0.57，移除后降到 -0.01 附近。
逐像素看更直观：移除前是 `91,82,72,69,70,69,72,82,92,92,82,72…`（清晰的 9 像素循环），
移除后是 `72,72,72,72,72…`（纯色 + JPEG 噪声）。

注意：**删掉网点后底色的调整空间更小了** —— 陆地从"有点阵纹理"变成了"一整块纯色"，
再往深里压会更容易和页面底色糊在一起。

### 亮点配色与底图亮度是耦合的

底图调亮会顺带毁掉亮点：亮点用的是**加法混合**，底图变亮（尤其蓝色分量上升）后，
原来的配色 `(0.62,1.0,0.80)` + 纯白芯会把蓝色通道顶到饱和，
亮点从「薄荷绿」退化成「白色/青色」—— 实测绿色可辨识像素从 100% 掉到 **0%**。

现在的取值（`THEME.dark.mark / markOpacity`）：`mark=(0.24,1.0,0.42)`、`hot=(0.66,1.0,0.55)`、`markOpacity=0.92`。
`node tools/verify_markers.js <URL>` 会 A/B 关开亮点图层量化「可辨为绿」的占比，
调整配色后请确认这个指标 ≥ 50%（当前深色 60%、浅色 34%，浅色是深绿点按普通混合，判据不同）。
`tools/tune_markers.js` 可以在不改代码的前提下批量试配色。

### 亮点尺寸：数量上去了，尺寸必须跟着调，否则等于白加

亮点从 2816 改成全量 8464 之后，第一版我把尺寸也按比例缩小了
（`base` 0.0104 → 0.0090），结果 **视觉密度几乎没变** ——
亚洲视角的亮点覆盖率只从 0.83% 涨到 1.11%，因为点数变多、点变小，总量抵消了。

调参要用数据说话：`tune_dots.js` 把候选参数注入运行中的页面，
逐个截图再做「亮点开/关」差分，量覆盖率。最终定在
`THEME` 之外、构造函数里的 `this.dot = { base: 0.0160, head: 0.0240, ref: 46, exp: 0.09, min: 0.72, max: 1.0 }`：

| | 旧版（2816 点） | 现在（8464 点） |
| --- | --- | --- |
| 亚洲视角亮点覆盖率 | 0.83% | **3.75%**（4.5 倍） |
| 单个亮点的渲染直径 | 约 2.6px | 约 4.0px |

`base` 是单点尺寸（世界坐标单位），实际像素大小 ≈ `base × 画布高 × 0.87 / 相机距离`
（见 `VERT_MARK` 里的 `gl_PointSize`）。
`dens = (ref / 该国亮点数) ^ exp` 再乘上去做密度自适应，`exp` 越大密区点越小。

## 交互细节里踩过的坑

### 全屏时画面正中会浮出播放三角

CSS 里原本有一条 `.stage.is-playing:hover .stage-big{opacity:.55}`，
想让鼠标悬停时给个播放/暂停的提示。但**全屏的是 `.stage` 本身** ——
全屏后整个屏幕都算 hover，鼠标一动三角就出现在正中央，很影响观感。

同时那个按钮**不能直接删**：它 `inset:0` 覆盖整个画面，是**全屏下唯一的播放/暂停点击区**
（底部控件栏只有静音 / 音量 / 全屏，没有暂停键）。

现在的做法：

- 播放中一律 `opacity: 0`（连 hover 也不显示）；暂停时才显示，充当「点一下继续」的提示
- 画面里有「正在连接」「点击播放」这类文字时也隐藏（`.stage.has-msg`），避免压字
- 另加一条**全屏专用控制条**：右下角两个圆钮（暂停/播放 + 退出全屏），
  鼠标移动淡入、停手 2.6 秒淡出

**怎么证明"确实没画出来"**：`opacity: 0` 只能说明计算样式，不能说明没有绘制。
可靠做法是把视频层 `visibility: hidden`（画面变纯黑）再截图 ——
中央区域均值 **0.00**；再把三角人为打开作对照，均值 **72.23**。
两边对比才是有效证据。

（我第一版是直接比较「播放中」和「暂停中」两张截图，得出「0% 一致」，
其实全是直播画面逐帧变化造成的，那个做法无效。）

### 命中检测的性能与触屏命中半径

亮点从 2,816 个加到 8,464 个之后，`hitTest` 成了热点 —— 它每次鼠标移动都要跑一遍。

- 原来逐点调 `Vector3.project()`（每点两次 4×4 乘法 + 新建临时对象）。
  改成先把 `view × projection` 预先乘成一个矩阵，每点只做一次 4×4 乘法，
  实测 **0.09ms/次**（8,464 个点）。
- 再加一层：指针位移不足 2px 就跳过命中检测。
- **触屏命中半径**：鼠标用 19.5px 半径够，手指接触面约 8~10mm，
  手机上必须放宽到 30.8px（`hitR2` 从 380 提到 950），否则点亮点经常点不中。
  判定用 `matchMedia('(pointer: coarse)')`，并在首次收到 `pointerType === 'touch'` 时再兜一次。

### 亮点尺寸必须跟着数量一起调，否则等于白加

亮点从 2,816 改成全量 8,464 时，第一版顺手把点也缩小了（`base` 0.0104 → 0.0090），
结果**视觉密度几乎没变** —— 亚洲视角的亮点覆盖率只从 0.83% 涨到 1.11%，
因为「点变多」被「点变小」抵消了。

不要凭感觉调，用 `tune_dots.js` 批量试 + 差分量覆盖率。最终定在构造函数的：

```js
this.dot = { base: 0.0160, head: 0.0240, ref: 46, exp: 0.09, min: 0.72, max: 1.0 };
```

覆盖率 0.83% → **3.75%**。像素尺寸的换算在 `VERT_MARK` 里：
`gl_PointSize ≈ aSize × 画布高 × 0.87 / 相机距离`，
所以 `base = 0.0090` 在 900px 画布、相机距离 3.1 时其实只有 **2.3px** —— 之前一直偏小。
